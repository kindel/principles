# Schema

`data/index.json` is the manifest. `data/<company>/<id>.json` is one principle.
Nothing else in this repository is data, and nothing here knows about any
application that consumes it.

A consumer picks one company and shows only that company's set.

## index.json

```json
{
  "version": 2,
  "generated": "scripts/build_index.py",
  "companies": [
    {
      "id": "amazon",
      "name": "Amazon",
      "set": "Leadership Principles",
      "source": "https://www.amazon.jobs/content/en/our-workplace/leadership-principles",
      "principles": [
        { "id": "customer-obsession", "name": "Customer Obsession", "sort": 1,
          "file": "data/amazon/customer-obsession.json" }
      ]
    },
    {
      "id": "arm",
      "name": "Arm",
      "set": "10x Mindset",
      "source": "https://careers.arm.com/life-at-arm",
      "principles": [
        { "id": "own-it", "name": "Own it", "sort": 8,
          "file": "data/arm/own-it.json" }
      ]
    }
  ]
}
```

Generated by `scripts/build_index.py`, never hand edited. `scripts/validate.py`
fails when it drifts from the record files. It exists so a browser can discover
the sets without globbing a directory.

## data/&lt;company&gt;/&lt;id&gt;.json

Amazon records do not carry `group`:

```json
{
  "id": "customer-obsession",
  "company": "amazon",
  "name": "Customer Obsession",
  "sort": 1,
  "definition": "Leaders start with the customer and work backwards.",
  "terms": [
    { "id": "co", "label": "CO", "kind": "alias" },
    { "id": "customer-advocacy", "label": "customer advocacy", "kind": "equivalent" },
    { "id": "user-empathy", "label": "user empathy", "kind": "facet",
      "rows": ["product-design", "responding-to-a-complaint"] }
  ],
  "rows": [
    { "id": "product-design", "situation": "On product design",
      "under": "...", "justRight": "...", "over": "..." }
  ]
}
```

Arm records carry `group` for the lens (`one-arm` or `accelerate-impact`):

```json
{
  "id": "own-it",
  "company": "arm",
  "group": "accelerate-impact",
  "name": "Own it",
  "sort": 8,
  "definition": "Be accountable for the outcome; don't wait for instructions. Bring solutions, not problems.",
  "terms": [
    { "id": "own-it", "label": "own it", "kind": "alias" }
  ],
  "rows": [
    { "id": "accountable-for-the-outcome", "situation": "Being accountable for the outcome",
      "under": "...", "justRight": "...", "over": "..." }
  ]
}
```

## Rules

- `id` is kebab-case and matches the filename without `.json`.
- `company` is kebab-case and matches the parent directory. Current companies
  are `amazon`, `arm`, `coupang`, `delivery-hero`, and `gitlab`.
- `group` is optional. Arm records carry it (`one-arm` or `accelerate-impact`)
  because Arm's set is published under two lenses. No other company's set is,
  so no other record carries it.
- `sort` is unique one through n per company, in teaching order, following the
  order the company itself publishes. Amazon is Customer Obsession first and
  Deliver Results last (one through 14). Arm is Passion for the mission first
  and Optimize for endurance and resilience last (one through 10). Coupang is
  Wow the Customer first and Hate Waste last (one through 15). Delivery Hero is
  Own It first and Stay Humble last (one through six). GitLab is Collaboration
  first and Transparency last (one through six), the order that spells CREDIT.
- `definition` is the company's short statement of the principle, transcribed
  from the company's own published page. It is a quotation, so it is never
  condensed, reworded, reordered, or merged. Where the published statement runs
  long, take a leading excerpt of whole sentences rather than summarizing.
  Three normalizations are allowed and nothing else: strip markup, fold
  punctuation to ASCII, and correct an obvious typographical error.
- File paths in the manifest are `data/<company>/<id>.json`.
- Nothing lives at `data/*.json` except `index.json`.

### terms

The vocabulary a person might use to name this principle. One list, three kinds.

- `alias` is the short form used at that company. Abbreviations and everyday
  names, `bfa`, `own it`, `one arm`.
- `equivalent` is how everyone else says it, and it means the whole principle.
  `move fast`, `do more with less`.
- `facet` also means how everyone else says it, but it names one slice of the
  principle rather than all of it. A facet must carry `rows`, listing the row
  ids it covers.

`id` is the slug of `label` and must be unique within a company, not globally.
A consumer addresses a term by company and term id. Two labels that slug to
the same id are the same term, so `think big` and `think-big` may not both
appear in one company.

The distinction between `equivalent` and `facet` is the point of the list. A
consumer showing results for an equivalent shows everything it has for the
principle. A consumer showing results for a facet shows only what maps to
those rows, so someone who asked for `user empathy` is not handed the whole
of Customer Obsession back.

### rows

The calibration taxonomy, and the anchor a facet points at.

- Five to 12 real situations per principle. Give each a kebab `id` and a short
  `situation` label.
- `under`, `justRight`, and `over` are one to three sentences each. They
  describe one behavior under indexed, balanced, and over done.
- Row ids are unique within a principle. A facet may only reference a row on
  its own principle.

### Style

Every authored string: no em dash, no `---`, Oxford commas, numbers under 10
spelled out. That is `situation`, `under`, `justRight`, `over`, and term
labels.

`definition` is quoted, not authored, so the company's punctuation and grammar
stand even where they disagree with the rules above. Pick an excerpt that
carries no em dash, because the validator rejects one wherever it appears.

## Consuming this repository

It is a Go module, so a Hugo site can mount it:

```
module github.com/kindel/principles
```

An application that serves JSON to a browser from its own origin should vendor
a pinned copy into its own tree with a script, and check that the copy still
matches the pinned tag. A copy is acceptable when it is generated and verified.
A copy kept in step by a human reading this file is not, which is the mistake
this repository exists to correct.

A consumer must pick a company and show only that company's set.

Version with tags. A schema change is a major version, so consumers can move
at their own pace.
